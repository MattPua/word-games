# Couch Potato

Swipe adjacent letters on a square or honeycomb grid. Casual word game — short sessions, fast first success, no hints.

## Game rules (engine owns these)

- Grids 4×4 / 5×5 / 6×6; topology **square** (8-way) or **hex / Honeycomb** (6-way odd-r); **no tile reuse in one swipe**
- **Rotate:** same letters, new view — **90°** CW or CCW (separate controls). Letters-only remap (never re-gen). **Square:** CSS board spin (~300ms) then remap; input locked mid-spin only — unlock on animation end (no extra beat). Glyphs **and tile face gradients** counter-rotate so letters + lighting stay screen-upright (avoids gradient snap when angle resets). **Frame chrome + box-shadow stay on non-rotating `.cp-board-frame`**; only inner `.cp-board-spin` transforms (idle `transition: none` so angle remap doesn’t reverse-spin). **Hex / reduced-motion:** instant remap (90° container spin can’t land on odd-r honeycomb).
- Tiles stay for the round (reusable across words)
- Min word length: global floor **3**; per-game setup may raise to **4** or **5**. **No artificial max** — any dictionary word that fits an adjacent no-reuse path counts (up to N² tiles on an N×N grid). Lobby “3+/4+/5+” is a floor only; gen `ge6` thresholds are quality floors for words ≥6, not a ceiling. Gen prefers **≥1 word of length ≥6** (ideally 6–7 for challenge) on every board when possible; retry scale never drops that floor below 1, and best-effort fallback still ranks long-word boards higher when full thresholds can’t clear
- No duplicate words per round
- Dictionary: [dolph/dictionary](https://github.com/dolph/dictionary) — **v1 play lexicon = `popular.txt`** (enable1 ∩ Wiktionary TV/movie frequency lists ≈ 25k common words; not a frequency CSV). Web cold path ships **`popular.json` only**; full `enable1` is a split artifact (`enable.json` / `loadEnableWords`) for a future “dictionary mode” and **does not** drive accept, board `allWords`, targets, or missed reveals. Plus **offensive/NSFW blocklist** (ENABLE public domain — attribute in README). Blocked tokens must not appear in validation, board gen, or missed-words.
- **Board letter mix scales with difficulty** (`LETTER_VARIETY` in `config.ts`): common-biased `LETTER_WEIGHTS` get flattened per-tile (`letterMixWeights`) and already-placed letters get docked so one board doesn't over-repeat. Easy stays common-biased with just enough anti-repeat to avoid mono-vowel soup; Medium balances common + uncommon; Hard leans into rarer letters and penalizes repeats harder for real variety pressure. Timed has no difficulty knob — defaults to the Medium mix. Never overrides gen thresholds — a spicier mix that can't produce enough words still loses to the best-effort fallback board.
- Scoring: `points = length - 2` (config constant)
- **Goal** (UI; engine `mode: "target"`): countdown — `remaining` starts at achievable target (board max × `TARGET_RATIOS` Easy **0.30** / Med **0.60** / Hard **0.65**); each accepted word subtracts its points; **win when remaining === 0** (“Clear the couch”). Ratios are of **points** (`length − 2`), not word count — calibrated so short-first casual play hits ~p50 / p75 / p80 of board words (pts% ≪ word% because 3-letter finds are 1pt; literal 0.50/0.75/0.80 of maxScore would force near board-clear). High scores still store **points earned**. Max/target use only words ≥ active min length. Lobby card: Goal / Clear the couch, not “High score” (collides with Timed haul / Potato Board bests).
- **Timed**: fixed board; 30/60/90/120s → results (score accumulates; unchanged). Lobby: Timed / Beat the clock.
- **Survival** (UI; engine `mode: "survival"`): countdown clock, no points target — starts at `SURVIVAL_START_SECONDS[difficulty]` (Easy generous, Hard stingy, `config.ts`); each accepted word refills it via `survivalBonusSeconds(points, difficulty)` = `points * SURVIVAL_SECONDS_PER_POINT * SURVIVAL_BONUS_MULTIPLIER[difficulty]`, rounded, floored at `SURVIVAL_MIN_BONUS_SECONDS` (never a 0s refill); ends `timeout` when the clock hits 0 (reuses `tickTimer`, same as Timed). Points still accumulate for haul/high scores. Difficulty picker reused from Goal (**How hard?**, not duration chips). Lobby: Survival / Keep the clock fed. High scores keyed by mode × difficulty like Goal.
- **Quit mid-game** (UI: **End run**) → results with progress so far (`won` | `timeout` | `quit`)
- **Pause menu** (play): Escape or HUD pause → **Couch break** overlay — choice cards for SFX / Lobby jam / Words left / Look, then pixel `border-t` before bottom run-control row (**End run** left destructive ghost/`cp-end-run-btn` | **Resume** right primary); pauses timed clock + blocks grid swipe until Resume / second Escape

## Product surface

- **Home setup = game lobby** (not a settings form): **Primary** — mode cards, board picker (size + Square/Honeycomb), challenge (How hard? / How long?). **Customize your game** (quieter advanced column) — Min length choice cards (helper + 3+/4+/5+ hints). Phone: stack primary → advanced. Wide web: primary left | advanced right; cards hug content. Play dominates; sticky Play bar = Play (+ compact **Last results** / Last haul `History` icon in the same cluster when this profile has a finished run — opens full `/results` from persisted `saveLastRun` / `loadLastRun`; profile-scoped localStorage; no music/SFX); narrows on md+ lobby (centered cluster, not full shell width). Header chrome nav: **Back to lobby** (`Sofa`, leftmost, hidden on `/`), **Couch medals** (`/achievements`), **Couch crew** (`/profiles`), **Options** (`/options`) — icon buttons with tooltips; on md+ a quiet shadcn `Kbd` ⌘K / Ctrl+K chip after the icons opens the palette (hidden on phone). **Command palette** (⌘K / Ctrl+K): shadcn `CommandDialog` jump to Lobby / Play / Options / Couch crew / Couch medals / Last results (when `loadLastRun` exists), plus **Options pref flips** (one action each: Switch Look to Day/Night, Use Clean/Pixel titles, Hide/Show words left, Turn SFX/Lobby jam on/off) that apply immediately and close the palette. Device prefs are **not** on the lobby or Couch crew. Optional Dark mode duplicate in Couch break mid-run. See `.cursor/rules/ui.mdc`.
- **Options** (`/options`): device prefs as 2-option choice cards (Look Day/Night, Titles Clean/Pixel, Words left Hide/Show, SFX Off/On, Lobby jam Off/On) — not switches. Compact `max-w-md` centered column (not wide `cp-shell-crew`). Not profile-scoped.
- **Last results** (lobby → results): after any completed/quit/timeout run, `storage.ts#saveLastRun` keeps the full results payload (found/missed/score/reason/medals peek) per active profile in localStorage. New run overwrites; profile switch loads that crew's last run (or hides the control). Not Couch crew history — direct path back to the full results screen.
- Local profiles only (no cloud/export/sync); high scores per profile × grid × **topology** × mode × difficulty/duration. UI label: **Couch crew** (route may stay `/profiles`) — crew roster, Potato Board, medals teaser; **not** theme/font/device prefs (those live on **Options** `/options`).
- **Potato Board** (personal local stats on Couch crew): games/words totals, lifetime **Words / min** + **Avg length** (pace aggregates in `profileStats.ts`), bests with timestamps, recent runs (last 20). Not a cloud leaderboard. (“Alita Board” speech → this.)
  - **Pace defs:** avg WPM = `wpmWords × 60 / playSeconds`; avg length = `totalLetters / lengthWords`. Time base = active play (Couch break pause excluded): Timed = sprint elapsed (`duration − remaining`); Survival = time lasted; Goal = wall-clock while unpaused. Runs with no usable time still update avg length, skip WPM. Missing `pace` on old profiles → zeros; WPM may seed from recent Timed history (sprint length); letter totals start fresh.
- **Achievements ("Couch medals")** — local per-profile progression, `apps/web/src/achievements.ts` owns all track/milestone math (UI never recomputes). Staged tracks (ascending milestones, fast-then-meatier): lifetime **Points haul**, **Word collector** (unique words), **Couch sessions** (runs completed, from `Profile.gamesPlayed` — not duplicated in the achievements blob), length hauls (**3/4/5/6/7/8/9+-letter finds**, occurrences not unique; legacy `7plus` migrates into `7`), single-run records **Best haul** + **Word rush**, and Survival hooks **Longest survival** + **Survival hauls** (populate once `RunHaul.mode === "survival"`). Persisted on `Profile.achievements` (`AchievementCounts`, migrates safely via `normalizeAchievementCounts`); `AchievementContext` = counts + injected `gamesPlayed` for progress math/rendering (`withGamesPlayed`). **Unlock dates:** `stageUnlockedAt` on the counts blob (`Partial<Record<TrackId, number[]>>`, epoch ms; index `i` = stage `i + 1`); stamped by `applyRunToAchievements` on each newly cleared stage (never overwrites; missing = legacy/unknown — UI must not invent). Exposed on `TrackProgress.unlockedAt` / `stageUnlockedAt` and `StageUp.unlockedAt`; display via `formatUnlockDate` (“Unlocked Jul 25, 2026”). `/achievements` shows current-stage date; Results peek shows date under fresh stage-ups. `storage.ts#recordFinishedRun` applies each run (`applyRunToAchievements`) and returns a snapshot + `StageUp[]` + touched track ids. **Track UI** (`AchievementTrackRow`): show only the **active milestone** (`TrackProgress.currentMilestone`) + bar progress toward that next medal + a short remaining-lock note (`formatRemainingStages` → “3 still locked” / “All unlocked”); never list every stage pip. Cleared tracks stay full-bar + last milestone + “all unlocked”. Results peek (`ResultsMedals`) stays compact (no milestone dump). Full page `/achievements` (linked from lobby, Couch crew, results) groups into "The big picture" / "Personal bests" / "Length hauls" / "Survival". Page chrome: `ScrollShell` + `cp-shell-medals` / `cp-medals` (widens on md+); wide `.cp-medals-columns` = 2×2 track groups (`align-items: start`).
- SEO: strings in `apps/web/src/seo.ts` (cold-load via Vite `transformIndexHtml` → `index.html`; per-screen titles via TanStack Router `head` + `HeadContent`). JSON-LD `WebApplication` / `VideoGame`.

## Code style

TPP DRY: one authoritative place per piece of knowledge. No over-abstraction, no one-export files. Engine decides; UI displays. Format with `oxfmt`; lint with `oxlint` (see `.cursor/rules/coding.mdc`).

**Commits:** [Conventional Commits](https://www.conventionalcommits.org/) — imperative subject, concise. Types: `feat:`, `fix:`, `docs:`, `style:`, `refactor:`, `test:`, `chore:`; optional scope: `feat(engine):`, `fix(play):`. Examples: `fix(play): stop last-catch from shrinking the board`; `feat(engine): vary board letters by difficulty`; `docs: document shared chrome-devtools browser`; `style(ui): remove hard bezel from switch rows`. Don't rewrite history to fix old messages.

## Agent UI verification (required)

UI work is **not done** until interactively verified in a running local app (pointer swipe across tiles — not click-only). See `.cursor/skills/verify-ui`. Engine-only → Vitest; UI → Vitest **and** interactive check.

**Browser QA:** `chrome-devtools` MCP is configured (`~/.cursor/mcp.json`) to attach to one shared debuggable Chrome (`--browserUrl`, port 9222) instead of launching a new Chrome App per call — see `.cursor/skills/verify-ui` for the start script and etiquette (reuse it, don't spin up a parallel Playwright browser when devtools suffices, don't fight another run's open tabs).

**Mobile:** agent default is **Expo web** (`bun run mobile:web`) + Playwright smoke — see `.cursor/skills/verify-mobile`. Optional iOS Simulator boot when native launch matters. Full play QA remains on web until Expo play ships.
